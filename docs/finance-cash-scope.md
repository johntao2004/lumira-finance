# 按月现金范围资格复核

本章为 `finance@0.4.0` 已在独立本机 QA 环境验证的产品合同。来源及本地事件能力继续保留，证据见[来源事件与本地事件处理](finance-source-events.md)。后续未核实现金来源登记候选的代码和证据与本版本分开记录。

## 支持范围

在新 V4 精度、开放年度及开放月份，为一个法人账套编制一个完整自然月的现金范围。企业准则使用 `CAS-CF-2019-A2`，小企业准则使用 `SBE-CF-2011`；会计制度不产生税务资格。

本片只接收库存现金或活期存款，每个范围含 1—20 项。每项必须由编制人主动声明“该年度科目仅对应一个独立现金工具或账户”，选择年度借向资产科目，填写资格依据并关联本账套、年度中实际保存的原件。混合银行总账科目、多个银行共用一个科目、投资等价物、合并范围、外币及月中范围变化尚不支持。

每项保存纳入或排除决定、使用限制、是否可随时支取及依据。纳入要求无使用限制且可随时支取；排除项仍保存理由与原件，不能无依据地当作不存在。单工具声明及人工复核没有替代银行账户身份域或银行验真。

现金范围资格批准没有建立实际现金流水、银行文件覆盖、收付分配、内部划转配对、退款额度或正式现金流量表。总账分录及余额也不会自动生成实际现金事实；正式三表入口仍保持阻断。

## 编制与独立复核

入口为企业财务工作台的“现金范围”。有账套及年度阅读权限的成员可查看范围与证据；OWNER 同时有平台 manage 和 create 才能编制及提交自己的草稿。OWNER 或 REVIEWER 且有平台 approve 才能独立批准或驳回。

内容创建后不可编辑；变更应重新编制草稿。状态依次为 DRAFT → SUBMITTED → APPROVED 或 REJECTED。提交和审签都绑定服务端版本、`contentVersion` 与 `contentDigest`；不存在忽略摘要的快捷批准。编制人及最后编辑人不能审签自己的范围。这里的独立检查以平台账号 UUID 为边界，同自然人多个账号的可信关联尚未实现，不能据此宣称完整自然人职责分离。

批准时重新检查编制人的现时管理、制单及年度授权，并比对实际年度科目快照、原件字节及服务端摘要。授权撤销或快照失效时批准被阻断；独立复核人仍可在版本和原始内容摘要正确、年度及月份开放时驳回该申请，记录拒绝理由。

每个账套、年度、自然月最多一个批准范围。并发批准须串行保护并受数据库唯一约束；成功批准只递增一次 `scopeVersion`。本片不提供覆盖批准范围、同月替换或自动生效变更。

## 原件与可追溯版本

编制页可直接上传原始字节并选中服务端原件 ID，无需先建无关凭证；单件上限沿用 5MiB。电子原件和纸质扫描件由用户选择，纸质件须登记实体原件保管位置并保存于依据说明。服务端验证存储字节与 SHA-256；这没有产生真实性、电子签章或保管移交结论。

详情提供原件下载，复核人可查看实际证据。下载仍经过原件范围鉴权；页面切换时取消请求、清理缓存并释放临时下载 URL。

当前年度科目没有独立可变数字版本，本片保存真实年度科目 ID、完整字段快照及其内容摘要 `accountVersionDigest`，不虚构“版本 1”。范围保存原件 ID、文件名、服务端 SHA-256 及真实原件版本；法人、账套、年度、期间、科目和原件关系均须一致。

独立现金范围守卫记录批准代次。读取范围列表和详情时，在一致快照中返回现金范围代次及既有年度财务水位；现金范围复核不修改凭证、过账事实、正式期初或既有年度财务水位。

## 持久化与接口

新 V5 迁移只增加 `plugin_finance_cash_scope_guard`、`plugin_finance_cash_scope_revision`、`plugin_finance_cash_scope_item` 及相应约束、索引、状态保护。已发布 V1—V5 的身份与校验和冻结；没有 repair、重置数据库或重编码历史数据的步骤。

接口位于 `/api/finance/v1/books/{book}/years/{year}/cashflow/scope-revisions`，提供有界游标列表、详情、编制、提交、批准和驳回。请求字段封闭、写入保留幂等键；重放前先重新校验现时权限、年度及月份门禁。完整 DTO 及请求头合并约束见 [OpenAPI](finance-api.openapi.json)。

所有修改依次取得请求键、账套、年度守卫、现金范围守卫、期间和记录保护，并在同一事务内提交状态、范围代次、审计及幂等结果。批准与驳回后记录不可改；内容和明细快照不因后续查询而重新计算。

旧精度年度及非开放年度、月份不开放范围写入；查阅原记录仍受现时阅读授权约束。待归档年度不会因完成范围复核、技术投影或原件下载而变为最终完成。

## 验证边界

实际后端回归 44 项报告均通过，其中 36 项为真实 PostgreSQL、6 项为 Controller 边界、2 项为原件单元测试。完整 44 项通过后，针对新增法人快照数据库约束再定向运行 5 项现金范围测试通过；旧 39 项对应生产代码未变。三个 JDK 25 领域验收程序、13 项前端逻辑测试、完整前端类型检查及插件打包通过。构建和重测试串行执行，采用受限堆及单测试 fork。

实际 HTTP 在 CAS 和 SMALL 分别上传测试原件字节、编制三月范围并由独立账号批准。声明缺失或为 false、模板错配、跨租户原件、自审、陈旧内容摘要、重复批准及同月替换被拒绝；原键批准重放没有重复递增范围代次。读取和修改均受现时范围及动作授权限制，待归档年度不能写入。

浏览器实际完成四月 CAS 范围：未主动声明时客户端不发送创建请求；直接上传原件后服务器哈希一致；保存与提交不可变草稿；编制人批准按钮禁用；独立复核账号下载的字节哈希与原件一致，批准绑定原内容摘要，范围代次由 1 变为 2，终态审签按钮禁用。另检查 SMALL 使用独立模板、切换后没有 CAS 四月记录；模拟现金范围读取 403 后，账套、年度与旧数据一起回收。该模拟只证明界面响应；真实越权由 HTTP 和数据库测试另行验证。没有声称移动端、视觉设计、真实性或生产容量验收。

实际请求及响应的 11 组载荷通过 JSON Schema Draft 2020-12 与格式验证，匹配封闭的 OpenAPI DTO。资格、原件及独立审签已接入，流水覆盖、收付分配、现金流贡献、完整三表及阶段 B 仍未放行。

QA 升级前已生成专属数据库备份并验证归档目录可读；以 PRESERVE 卸载、导入和安装 0.4.0，未重置或恢复数据库。升级前后旧财务事实、来源、稳定效果、回执及不可变 Outbox 证据指纹一致。完整 HTTP 和浏览器流程后再次核对：全部凭证、分录、过账和期初指纹均未改变，来源链也未改变；范围批准不产生财务记账。
