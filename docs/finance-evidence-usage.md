# 单据用途与费用归属

本切片依据 V4 EV03、PAGE-EV03 和工程包的额度事务协议实现。`0.15.1` 已完成独立 QA 保数据升级、真实接口、浏览器及最终关系核验的受限验收。本文描述实际范围，不表示完整报销、付款或会计系统及完整 V4 已交付。

## 单据身份与原件

原件文件记录保存真实字节、服务端 SHA-256、上传人和原账套年度。独立法律单据记录使用企业法人范围内的单据类型、开具机构稳定标识和单据唯一标识查重；文件哈希另作字节查重。同一文件或同一单据换年度登记，不能取得第二份费用额度。

法律身份的永久查重范围为平台租户与法人，这是比参考工程包账套范围更保守的产品约束。首片实际读取、引用和消费限于原账套、原年度；跨范围重复命中须拒绝，不能因此扩大原文件的可见范围。未授权用户不得获知旧单据身份或余额。原始主文件不可替换；其他扫描版本、自动拆票、跨单据合并和跨年度消费尚未开放。

登记者必须主动声明一个文件只对应一张独立单据、已声明全部已知标识、资料属于同一单据。来源明确区分电子原件与纸质扫描件，纸扫必须记录实体原件位置。上述声明及后续独立组织复核均不代表政府验真、电子签名验证或税务抵扣资格。

## 额度与真实业务份额

面额 `faceGross` 与允许费用归属的上限 `expenseCapacity` 独立复核，后者不得超过前者。登记会建立真实待审依据；当前 OWNER 提出，另一自然人按当前业务权限复核后才产生可消费的依据版本。零额度是已知零，尚未复核的额度是未知，两者不能混用。

| 用途 | 本切片行为 |
| --- | --- |
| 费用归属 | 支持真实草稿、提交预占、独立确认、退出及部分更正 |
| 结算分配 | 尚未支持消费，容量和余额返回未知 |
| 会计确认 | 尚未支持消费，容量和余额返回未知 |
| 税务用途 | 尚未支持，不产生抵扣或申报结论 |

各用途独立计量，不把三个阶段相加为一个占用总额，也不自动把面额复制为其他用途的合格容量。现有凭证参考附件、现金分类分配和来源复核均不会自动成为本切片的费用消费。

费用归属份额具有真实业务链、永久来源操作键、金额、发生日期、依据版本、准备人和内容摘要。草稿不占额度；提交产生绑定该次真实提交的 `RESERVED` 记录；独立确认产生确认决定并将该次消费变为 `COMMITTED`。同一用途不同业务链共享容量。更换 HTTP 幂等键不能重复创建同一来源操作，已释放的历史预占不能复活。

## 退出与更正

未确认份额可由原准备账号撤回，或由独立审核人驳回、行政终结，真实释放该次预占。原账号失权、过期、原期间关闭，不能把退出路径永久锁死；操作人仍须满足当前范围、岗位、人员绑定及相应认证要求。同人其他账号不继承原账号专有操作。

已确认份额不能直接编辑、删除或改成释放状态。部分更正必须建立新请求，由不同于本次申请人的自然人批准，并追加关联原确认与实际消费的更正效果；累计更正不能超过原份额。历史准备人或原确认人可以依当前权限处理更正，不额外要求第三个人。该效果仅减少费用归属净份额，不表示银行退款、付款撤销或总账冲销。

依据校正待审时暂停新增提交和确认，仍允许退出及减少净份额。批准新依据前须清完有效预占，且新费用上限不低于当前已确认净额；不要求先把真实已确认额虚假更正为零。旧确认保留旧依据快照，旧草稿必须显式编辑更新依据后才能再次提交。

## 权限与工程边界

首片写入要求年度已明确启用 `JOURNAL_PERSON_SOD` 且采用 V4 精度；新增使用须满足年度和发生期间开放规则。依据提议和更正申请要求 OWNER、相应平台业务权限与近期最终登录 TOTP；独立决定依当前 REVIEWER/OWNER 权限校验自然人。目录治理授权不能代替业务授权。原件可以先由有权限的员工上传，OWNER 登记时保留真实上传人。

新增表、事务函数、审计和迁移由财务插件拥有，迁移使用新的 V15 身份。V1–V15 已发布且永久冻结，不修改基座子模块，也不回填历史凭证的费用占用或独立批准。列表使用有界游标页和原范围授权水位；历史依据、更正请求采用逐笔前驱导航，不隐式加载全部历史。

单据 `version` 表示登记和依据复核的业务版本，费用桶 `version` 使用同账套年度的可读视图水位，随预占、确认、释放和更正更新，不能拿前者冒称新余额版本。准备人、最后编辑人和业务时刻绑定真实不可变事件；已退出草稿不能遗留未释放预占，数据库直接写入同样受双向约束。到期判断在取得必要锁后使用执行时刻，避免事务排锁后仍按旧开始时间放行。

代码为未来合法关闭年度保留退出与减少净额的处理，但现有 V14 人员模式年度尚未接入年结，不能合法关闭。当前数据库反例覆盖真实已关闭月份、失权准备人和排锁后到期；没有据此声称关闭人员模式年度已验收。
