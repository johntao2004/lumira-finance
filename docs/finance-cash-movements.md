# 未核实现金来源登记与完整现金行匹配

本章记录 `finance@0.5.0` 在独立本机 QA 环境中已经安装并验证的范围。两套会计制度分别验收；不将登记、总账或资格声明视为银行验真、完整现金流水或正式现金流量表。

## 登记及作废

入口为“企业财务工作台 → 现金来源登记”。有当前账套、年度阅读授权及平台 read 权限的成员可查阅；当前 OWNER/MAKER 且拥有 create 权限才可登记。登记不要求 manage。作废只能由原登记人以当前授权执行，其他 OWNER 或平台管理员没有代作废入口。

每行须由用户从独立原件、现金簿或银行流水主动填写稳定来源键、原件全文件行引用、日期、方向及人民币金额。客户端不从凭证现金行自动填入来源金额。服务端采用封闭的手工来源目录，来源与渠道均未核实；只支持当前列明的普通收付类型，不以 OTHER 接收内部划转、退款、净额、费用拆分或其他复杂业务。

登记绑定本月已经独立批准的现金范围、其中纳入且声明为单一工具的年度科目、当前科目快照和实际保存的依据原件。批准范围使用该月份自己的批准代次；其他月份新增批准不会替换它。独立来源原件另行上传、保存服务端 SHA-256，并绑定完整文件中的具体行。没有仅凭用户填写哈希的替代路径。

登记只比对同账套、年度、科目、日期及方向的一条真实 POSTED 完整现金行。金额按人民币输入最多两位小数严格校验；须与完整现金行一致，并绑定真实凭证版本、过账序号及摘要。不支持拆分、合并、补差或自动生成凭证。登记始终为 UNREVIEWED、UNCLASSIFIED、`reportContributionEnabled=false`，不向任何正式报表贡献金额。

稳定来源身份及“原件哈希 + 全文件行引用”永久防重。更换请求键、来源命名空间或目标凭证不能绕过同一来源行的墓碑；同一有效现金行同时只能有一个登记占用。原登记人可以撤回尚未核实的声明，状态变为 VOIDED，保留原始内容和证据，仅释放有效现金行占用。作废后旧创建键重放返回当前 VOIDED 详情，原缓存历史字节保留，不复活来源或释放稳定来源身份。

年度、月份必须开放且采用 V4 精度，写入及幂等重放都重新鉴权。旧精度、已关闭及待归档年度只能按当前授权查阅。来源事实错误、跨期变更、离职登记人接管和受后续业务使用的来源更正，均不属于 0.5 的能力。

## 持久化和兼容边界

接口位于 `/api/finance/v1/books/{book}/years/{year}/cashflow/movement-registrations`，提供目录、真实候选现金行、有界游标列表、详情、登记和作废。请求字段封闭，写入绑定内容版本及摘要，事务内提交登记、技术代次、财务审计和幂等结果；不修改凭证、过账、期初或现金范围批准代次。

V6 新增登记表及守卫、范围与真实过账关联约束、永久来源防重和不可变状态保护。V1—V6 的身份、字节及校验和已冻结。`downstream_use_count` 当前受 CHECK=0 限制，没有下游使用写入接口；不能将它称为已接入分配或真实使用保护。后续使用者必须建立实际类型外键、相同锁协议和使用状态检查。

0.5 的银行渠道没有联网、真实性验证或银行覆盖清单。单工具声明没有替代银行账户身份域。同自然人多个账号的职责分离仍未实现。现金流分类、逐行分配、内部划转与退款处理、完整覆盖证明及正式三表仍未放行。

## 实际验证

后端测试报告共 52 项通过：全套 52 项运行中新增 Controller 测试的 Mockito 重设写法失败，修正测试后定向重跑相关 8 项全部通过，合并报告无失败、错误或跳过，生产代码未因该测试修正而变化。另有 3 个 JDK 25 领域程序、18 项前端逻辑测试、完整前端类型检查和插件打包通过。各类测试分别统计，不将内存参考模型当作产品验收。

专属 QA 库先备份并验证归档目录可读，再通过固定 SDK 的 PRESERVE 卸载、导入和安装完成 0.4 → 0.5 升级。未重置、恢复数据库或改写历史迁移。升级前后原财务事实、原件、审计、幂等、来源链和已批准现金范围指纹一致。

实际 HTTP 在 CAS 和 SMALL 独立账套登记测试来源行并匹配已记账现金行。验证严格金额精度、金额与范围代次错配、非法命名空间及控制字符、同来源和同文件行防重、现金行占用、不同 OWNER 不可代作废、原登记人作废及旧键当前状态重放。临时 CAS MAKER 授权在检查后恢复为禁用，撤权后原创建键也被拒绝。跨租户同名来源在各自隔离范围独立存在。

浏览器实际完成 CAS 四月来源行：选择现金行后来源金额保持空白；填写不一致金额时客户端没有发出登记请求；正确填写后保存未核实登记；下载的实际原件与上传字节 SHA-256 一致；原登记人填写原因作废，详情终态按钮禁用，作废筛选可查到永久墓碑。HTTP 下载响应体不能代替浏览器下载文件，验收以实际保存的 170 字节文件及其哈希为准。

17 组实际 HTTP/浏览器请求及响应通过 JSON Schema Draft 2020-12 封闭字段与格式校验。为匹配测试，先通过正常制单、独立审核和记账准备了明确的 QA 现金行；随后建立指纹基线。全部登记和作废完成后，凭证、分录、过账、期初、年度守卫以及现金范围守卫、范围头和明细共 8 表的指纹与该基线一致。这项结论不将测试准备阶段的合法记账称为“没有新增记账”。
