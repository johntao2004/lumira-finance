# 凭证自然人分权协议

`finance@0.14.0` 已完成独立 QA 的保数据升级、真实接口和浏览器受限验收。本页记录其限定实施范围；生产部署、历史批准补核和完整 v4 尚未放行。

## 年度范围

模式以 tenant、账套、年度为边界。现有年度保留 `ACCOUNT_ONLY`；不把今天的人员绑定填入过去的制单和批准记录。只有 V4 精度、状态 OPEN、完整十二个月均 OPEN，且没有凭证、记账、期初、迁移基线、出入年结计划或来源制证效果的新年度，才允许申请 `JOURNAL_PERSON_SOD`。可以预先配置科目；科目数量不代表财务发生额。

启用需要具备现有平台管理权限的账套 OWNER 提出申请，再由另一自然人的当前 OWNER/REVIEWER 独立确认。两人必须具有有效组织人员绑定和对应年度权限，治理写入要求最近五分钟最终登录且会话通过 TOTP。该认证边界沿已固定宿主公开能力，不代表独立 MFA 事件时间或单项操作绑定认证。

模式单向启用，没有普通关闭或降级按钮。空年条件在申请及确认时由服务器完整查询，并与全部相关财务写入串行协调，不能以列表显示为空代替。年度初始技术代次不是批准记录。人员来源为组织人工核验断言，不是政府 KYC。

启用批准和实际模式切换限定为 READ COMMITTED，获得互斥锁后以当前快照重新检查空年；其他隔离级别的直接切换返回序列化失败并回滚。普通财务写入持共享模式锁，不通过每笔修改模式代次制造写热点。读取上下文仍采用一致的 REPEATABLE READ 快照；页面显示可申请不保证提交时条件仍成立。

## 内容、批准与记账

首片仅支持人工 `NORMAL` 凭证。制单、编辑、依据关联和提交使用当前实际账号及其有效人员绑定，保留原有岗位和原账号归属限制。同一人的另一个账号不会继承制单人的编辑、撤回或取消权限；普通业务人员不必拥有人员目录治理 assignment。

内容版本与流程版本分开。经济内容及依据由 PostgreSQL 生成固定格式规范快照和 SHA-256，包括日期、摘要、按行号排列的八位金额与科目、依据关联和服务器原件摘要。批准前可读取该版本的完整受限快照。仅状态变更不增加内容版本；规范内容完全相同的编辑也不增加内容版本，现有流程版本规则继续适用。实质内容或依据发生变化时产生新内容版本，旧批准不能用于新内容。

自然人批准比较当前审核人与冻结的制单人、最后编辑人，阻断同人不同账号自审。批准绑定真实凭证、流程版本、内容版本、摘要和期限，期限须在当前时间之后且不超过七天。记账必须引用该真实批准，重验当前权限、人员资格、内容及期间，并生成与真实记账序号、摘要对应的凭据。

本协议不默认增加第三人岗位。有独立有效批准后，制单人或批准者如具有既有 OWNER/POSTER 权限，也可以记账。现金业务的分权不由凭证批准替代。

新模式年度的旧账号级 approve/post 路径必须在幂等结果回放前拒绝，引导使用新协议；旧年度继续保留原行为。数据库约束同时要求真实内容、逐流程版本操作记录及批准/记账关系，旧二进制不能仅更新状态就跳过新模式保护。

## 退回和离职处置

新模式允许当前独立审核人将 SUBMITTED 或尚未记账的 APPROVED 凭证退回 DRAFT，必须留下真实原因、账号、人员及版本记录。原批准永久保留，并在当前投影中标为失效；过期或原批准者离职不应使对象永久锁死。`ACCOUNT_ONLY` 的 reject 仍只处理 SUBMITTED，POSTED 永远不能退回。

原制单人离职留下的 DRAFT 可以由当前独立审核人行政终结为 CANCELLED，保持原制单账号与分录，单独记录行政决定。对于离职制单人的 APPROVED，先独立退回，再行政终结，保留两次实际决定；不冒充原制单人、不更换 creator，也不自动复制洗掉历史。普通原制单人取消与行政终结须明确区分。

## 本片阻断和验证状态

来源制证、冲销、系统损益/年末结转暂不接入本协议，在新模式年度由服务及数据库共同阻断。年结计划、批准、执行如来源或目标年度任一采用新模式，也被阻断，直至年结有自己的自然人凭据协议。原历史和只读查询保留；月结没有因本协议获得双人确认能力。

接口使用独立模式上下文、启用申请发现、同版本凭证上下文、自然人批准、记账和行政终结操作。读取失败或切换范围会清除旧上下文；写入结果不确定时保留原正文与幂等键，显式读取状态后决定是否重试。界面禁用只是提示，服务器仍负责最终鉴权和事务约束。

已冻结十条新接口、十七个闭合 DTO；现有接口和历史验收组继续保留。验收覆盖同人多账号、普通非治理人员、无绑定和无 TOTP、依据/内容变化、批准过期、离职退出、旧路径回放、直接 SQL 反例、空年启用并发、旧年度兼容、CAS/SMALL 两制度、保数据升级和真实浏览器。各类验证须分开记录，尚未完成的浏览器部分不能由接口测试代替。

当前后端完整 33 suites、149 tests 通过，最后仅目录说明文字调整后另有 12 项目录定向通过；保留首次测试编译、迁移测试事务及反例前置状态的修正记录。真实 AOP 装配覆盖来源服务的 Gate 虚方法委派，避免代理字段未初始化问题。最终 TypeScript 检查及统一构建通过，3 个领域程序与 74 项前端规则测试保留源码等价记录。独立备份已完整恢复核对；PRESERVE 升级保持全部旧 64 张表，原 15 年度只建立 ACCOUNT_ONLY 技术守卫，未自动启用或回填。

## 独立系统结转协议扩展

0.14人工NORMAL协议的内容、批准和记账格式维持原样。0.16新增[独立结转生产者协议](finance-profit-closing.md)，仅真实Run关联的PROFIT_CLOSE／YEAR_END及其完整反向使用专用来源、内容与批准证明；不得调用旧NORMAL动作。该扩展不开放一般来源制证／冲销、现金人员分权或年度BASE执行。
