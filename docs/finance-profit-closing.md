# 人员协议损益结转

`finance@0.16.0` 已完成独立 QA 的保数据升级、真实接口及桌面／窄屏浏览器受限验收。本页记录已验证的人民币总账结转范围，完整 V4、正式年度关闭和生产部署尚未放行。

## 账务范围

首片面向明确启用 `JOURNAL_PERSON_SOD` 的 V4 人民币年度，两套会计制度分别验收。按真实年度科目用途识别本年利润及未分配利润，不猜科目编码。人民币分录必须符合两位入账精度；内部金额保留八位，借贷必须严格平衡。

- `PROFIT_LOSS`：在自然月末，按截止日实际已记账余额结清各收入、费用科目，差额转本年利润。余额包含此前实际结转及其反向分录；后续费用调整只结转剩余差额。同额收入与费用仍需逐科目清结，不能仅因净利润为零就省略。
- `YEAR_END`：仅 12 月 31 日，在损益科目实际余额已全部清零后，将真实本年利润余额转入未分配利润。生成或批准损益草稿不能代替正式记账。不能自动提取公积或分配股利。
- `TRANSFER_REVERSAL`：通过新凭证完整反向一笔真实已记账结转，保留原凭证与批准证明。仅支持原截止日仍开放、后续有效依赖已依次解除的场景；不自动级联，不支持普通凭证、部分结转反向或反向凭证再次反向。

此功能不切换月份或年度状态，不生成次年期初、BASE/DELTA 承接批次、正式财务报表或档案。旧 `ACCOUNT_ONLY` 年度维持原协议。

## 来源及不可变证明

服务器从权威总账计算来源和分录；客户端只能提交意图与预期版本，不能上传生成行或指定制备、审核身份。来源冻结截止日、实际纳入的记账水位、年度模式、期间和科目语义、余额及生成结果。未来日期记账单独影响年度观察水位，不应改变较早截止日的实际来源；纳入截止日的新记账即使净额为零，也必须使旧依据失效。

来源摘要和内容摘要使用独立的结转格式。旧人工 NORMAL 内容、批准和记账格式保持原样。结转 Run 与真实凭证、逐行分录、独立批准、实际记账及业务效果必须具有真实范围关系，并从两个方向核对；系统生成标志或一个 UUID 本身不能代表合法生产者。

原始表不新增用于放行的标志列。反向 Run 在创建时即通过真实关系冻结原结转凭证及其记账证明；未记账反向草稿的原始凭证 `reversal_of` 暂不物化，正式记账时在同一事务填入真实原凭证。这使已取消的草稿可以显式重建，同时保留旧表原有的一次生效约束。

## 审签、退出与重试

生命周期为 `DRAFT → SUBMITTED → APPROVED → POSTED`，生成内容只读。制备和提交由具有普通财务业务权限的当前有效人员账号处理，无需取得人员目录治理权限。独立审核按自然人排除制备人员及其其他账号，并验证当前审核权限、绑定和近期 TOTP 登录。正式记账要求当前记账权限及有效独立批准，允许原制备人或审核人在具有相应权限时记账，不默认增加第三人。

来源、资格或批准过期时不能悄悄重算旧行。原账号可撤回已提交凭证、取消草稿；独立审核人员可退回待审或已审凭证，再对草稿作行政终结。退出保留历史，不要求已离职制备人恢复资格；关闭月份仅允许带精确证明的未记账退出，不允许新生成、审批或记账。

每个 operationId 在范围内永久保留原始意图。同一操作或 HTTP 请求重试必须返回原 Run 的权威当前结果，不能在记账后因来源变化而生成第二笔。相同真实来源跨操作也要防重；取消后重建须显式绑定已取消的前序 attempt 与版本。后续真实记账产生新差额时，建立关联前序的独立补充 Run，原已记账行不修改。

## 接口及资源边界

独立入口为 `/api/finance/v1/books/{book}/years/{year}/profit-closing`，包括来源预览、分页 Run 列表、详情、真实凭证生产者解析，以及生成、提交、批准、记账、退回、撤回、取消和行政终结。旧 NORMAL 操作不会因本功能获得处理系统结转的权限。

协议限制最多 5,000 个来源科目、500 条生成行、每页 100 个 Run，写入正文上限 16 KiB；超过预算明确阻断，不截断权威余额。页面按真实账套、年度、账号、人员和授权上下文隔离，保留有界的同正文重试键。具体资源与运行保证须以实际测试结果为准，当前未建立百万级性能或生产高可用结论。
