# 受控来源事件与本地事件处理

本章描述 `finance@0.3.0` 已在独立本机 QA 环境验证的受控合同。它是 V4 来源制证及本地事件处理的子集，尚不代表完整财税产品或生产放行；后续现金范围候选与本版本证据分开记录。

## 来源与草稿

来源入口位于账套、年度范围下的 `source-events`。创建需要平台 `finance:manage` 和 `finance:create`，同时需要该账套负责人及年度授权；账套管理权限不能代替制单权限。只读查询和投影管理使用独立的管理权限，不自动授予创建能力。

当前受控范围只接收一条业务来源明细及明确的多条会计映射，生成普通凭证草稿。原件额度、来源冲销、辅助维度、外币、自动科目规则发布及对外 ERP 连接不在本入口开放范围。草稿仍须独立提交、审核和记账。

| 身份层 | 稳定键与约束 |
| --- | --- |
| 请求 | 当前授权主体、请求键及目标操作；重放前再次检查权限和年度门禁。 |
| 来源 | 租户、来源系统、稳定来源事件标识。同标识不同业务内容报冲突。 |
| 效果 | 服务端固定消费者、来源自然身份和效果类型。请求键、处理器版本、映射版本标签不能产生第二凭证。 |

金额采用十进制字符串。业务来源按内部精度保留，会计分录按人民币两位提交并校验平衡；不能为凑平静默舍入。来源明细关联及映射快照需要保存，以便从凭证追溯原始来源和当时的明确映射。

跨账套或年度重投必须检查原效果范围，不能通过修改目标建立重复效果，也不能向没有原范围权限的人返回原凭证信息。修改实际分录应形成明确更正流程，不能只换映射版本标签覆盖原效果。

## 事务 Outbox 与投影

来源、草稿、消费回执、审计和事件记录在同一事务提交；普通凭证的状态及内容变化也需要产生相应本地事件。任何一步失败均应回滚，避免有凭证无来源，或有回执无效果。

后台消费者只维护可重建的本地查询投影，不调用记账、申报、开票、付款或任意外部 URL。队列的 `DONE` 仅表示本地投影处理完成，不表示财务凭证已记账或外部业务成功。

任务通过固定基座的 `PluginResources` 注册，使用受管事务及数据库租约；每轮最多 20 条、调度间隔 5 秒，空队列逐步退避，失败重试有次数上限及最大等待时间。插件卸载须排空并关闭任务，不创建未托管线程。

管理重试不能抢占仍有效的消费租约。已关闭的有效 V4 年度允许恢复技术投影，不因此重新开放财务写入；旧精度年度、未知年度状态和未确认权限仍保守阻断。范围内重建从权威凭证读取，不删除原凭证、过账事实、Outbox 证据或稳定业务效果。大批量重建应走后续有容量约束的异步作业，不能一次将全部事实装入内存。

## 验证与未完成项

后端当前 39 项报告均通过：31 项真实 PostgreSQL 测试、6 项 Controller 边界及 2 项原件单元测试。首次全套中新增毒事件测试错误地期待损坏证据可以重试；保留实现的完整性拒绝并修正期望后，受影响的 7 项来源测试定向重跑通过，其余 32 项已在相同生产源码下通过。三个 JDK 25 领域断言程序与该版本 9 项前端逻辑测试通过；前端类型检查及插件打包通过。新增报告披露子集校验、现金流和小企业税费辅助函数仅证明领域算术边界，没有接通正式三表。

实际 HTTP 在各自租户的 CAS 和 SMALL 新账套，以相同外部来源标识分别完成 `100.01` 制证、独立审签记账，确认换请求键、处理器及映射标签不生成第二效果；实际内容冲突及越权访问被拒绝。SDK 后台任务将状态投影更新至 POSTED，投影重建不改变试算和过账水位。

浏览器通过 `agent-desktop` 的 CDP 交接和公开 Playwright DOM/交互验证：CAS 输入 `42.03` 生成草稿、查看初次映射快照、换处理器标签重投仍关联原凭证，查看本地投影状态；模拟一次读取失败后刷新恢复。独立 SMALL 会话看到自身已记账来源；切换至既有待归档年度后来源创建禁用，前一账套记录不残留。这些是实际交互与响应证据，未宣称移动端、视觉设计、全场景或生产容量验收。

在专属库备份并确认可读归档目录后，0.2.1→0.3.0 以 PRESERVE 卸载、导入及安装，旧财务事实与原件指纹一致。另实际测试 SDK 保留卸载和重新安装：卸载时两条事件仍为 PENDING，重装后均在一次消费中 DONE，投影为原草稿；财务事实指纹未变。此验证没有重置数据库、执行备份恢复或证明生产灾备。
