# Bounded archive packaging candidate

Node 24 built-ins only. Candidate has no registered routes, application state, DB queries, or dependency installation. `node --test archive-package.test.mjs` runs synthetic pure tests. No source data is included in this directory.

`validateIndex(index)` returns canonical UTF-8 bytes and `manifestSha256`. Deliver that digest over an independently approved channel. `pack(index, openOriginal)` is an async iterable of ustar bytes; openOriginal gets an original ID, never a path. It returns an iterable of <=64 KiB Uint8Array chunks. Stream output to private temporary storage, await successful completion, compute whole artifact SHA-256, offline verify it, and only then atomically publish; never expose partially generated output. The implementation owns each payload chunk before yielding; consumers must not mutate received chunks. Caller owns cancellation/deadlines and manages temporary artifact cleanup. Retain legal sources independently.

`verify(asyncIterable, trustedManifestSha256)` reads a canonical regular-file-only ustar subset without extraction, validates its index and every original hash, then returns explicit non-certification flags. `node verify-archive.mjs archive.tar <trusted-manifest-sha256>` works offline with Node 24. Archive contains index.json and originals/ files and can be read with standard tar tools; use the verifier before extraction. Do not open untrusted original formats in privileged applications.

Index format is defined by strict executable validation. All object members are closed except each audit's schema-neutral `payload`, which is canonical JSON with safe integer values, depth <=32 and aggregate metadata bound. Unknown fields, duplicate JSON keys (via canonical byte equality), invalid UTF-8, duplicate inventory IDs, out-of-scope year records, missing dictionary fields, dangling refs, unlinked originals/audits and tampered payloads are rejected. Audit payload hash uses this candidate canonical representation; the future adapter must also validate the original FinanceService or domain-specific audit representation before translating it. Do not replace stored historical hashes or imply that the package is a historical signature.

Dictionary field types are string, decimal and boolean (each with explicit nullable). Decimal values retain package precision 6 or 8; ledger-line debit/credit must be unsigned, while other decimal fields may be negative. Arrays/complex domain values must be normalized to separately identified records and refs or require a reviewed next format version. One package has one precision: multi-era export needs a reviewed bounded multipart format, not rounding six-place records to eight places. All ledger-line records contribute exact BigInt debit/credit totals; status filtering is adapter responsibility. These sums do not prove trial balance/report correctness. Dates and counters represented in record values should be string fields under reviewed domain dictionaries.

All nine coverage families must be explicit. Missing/unsupported blocks pack. NOT_APPLICABLE requires nonempty reason/evidence but semantic validity is an independent review gate. Verification can describe PARTIAL diagnostic packages, never full source completeness. Unknown totals remain null in partial indexes. There is no default count/totals fallback. IDs in this standalone format are bounded identifiers; future HTTP contract is stricter UUID. Snapshot/approval/sourceVector inputs are claims from the trusted adapter, not checked against a database by this pure component.

Bounds: <=4 MiB index, <=10,000 records/audits/originals each, <=200 dictionary types, <=100 fields/type, <=1 GiB/original, <=16 GiB original bytes/package, <=64 KiB chunks. Bounds may be lowered but not raised by callers. Retains one bounded index/graph plus chunks; not constant memory in record count and not million-record capacity evidence. Streams are cooperative: a producer that never yields/ends needs an external job deadline/cancellation. The verifier deliberately rejects trailing data, symlinks, extensions/PAX/GNU long names, noncanonical headers and even extra zero tar blocks. Standard tar readers can consume its output, but arbitrary external tar writers are not supported as producers.

Root integration still needs versioned semantic dictionaries, all-table authorized snapshot adapter, independent exact expected counts/totals, trusted approval and custody signatures/records, whole-artifact digest storage, scoped downloading/revocation, caller resource scheduling and cleanup, original readability/authenticity checks, qualified archive receiving workflow, and financial/report reconciliation. This is not ZIP-only complete legal archiving and does not establish ARC01/ARC03 acceptance.
